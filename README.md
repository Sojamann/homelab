# HOMELAB

## Stages

Set of stages executed in order where each stage depends on the preceeding ones

| Layer                                        | Tool      | Owns                                          |
|----------------------------------------------|-----------|-----------------------------------------------|
| [bootstrap](./bootstrap/README.md)           | by hand   | Controller, workstation, Cloudflare zone      |
| [network](./network/README.md)               | OpenTofu  | VLANs, DHCP pools, DNS records, firewall, wifi |
| [machines](./machines/README.md)             | by hand   | OS installs, ZFS pools, SSH keys, cluster     |
| [machine-config](./machine-config/README.md) | Ansible   | Host state                                    |
| [guests](./guests/README.md)                 | OpenTofu  | VMs and containers                            |
| [cluster](./cluster/README.md)               | OpenTofu  | Talos, Kubernetes, the CNI                    |
| [platform](./platform/README.md)             | OpenTofu  | Storage, GitOps, and what else workloads assume |
| [flux](./flux/README.md)                     | Flux      | The workloads themselves                      |

## Working with it

```sh
mise run network plan     # args are forwarded to tofu
mise run machine-config
mise run guests plan
mise run cluster plan
mise run platform plan
mise run s3 volsync ls s3://k8s-backups/   # aws s3 against Garage, key from the vault
```

### Updates
[Renovate](https://docs.renovatebot.com) opens a PR per available update, both
here and in `flux/` -- each repo has its own `renovate.json`. The PR is the
notification; the "Dependency Dashboard" issue lists everything outstanding.
Merging changes the pin only -- applying it is still `mise run <layer>`.

A release is proposed once it is 3 days old (immediately where the registry
has no release date, as with ghcr.io charts). The `flux` submodule pointer is
the exception: Renovate commits it straight to `main` whenever homelab-apps
moves, since Flux reads that repo directly and the pointer is only a record.
Tofu providers and modules are batched into one `terraform` PR, opened Monday
mornings.

Versions held in tofu `locals` are invisible to Renovate unless annotated on
the line above:

```hcl
# renovate: datasource=helm depName=cilium registryUrl=https://helm.cilium.io/
cilium_version = "1.20.3"
```

Datasources in use: `helm`, `docker` (OCI charts), `github-releases`. Add
`extractVersion=^v(?<version>.+)$` when upstream tags carry a `v` the pin does not.

## Secrets

`secrets/` is a submodule, and the repo behind it is private. Nothing
encrypted is committed here. Only the template is public:

| File | Where | Purpose |
|--|--|--|
| `secrets.example.yml` | here | template for `vault.yml`, with a comment per key -- what this lab needs to run |

The rest lives in the submodule:

| File | Committed | Purpose |
|--|--|--|
| `.vault-pass` | no | the ansible-vault password, unlocks the two encrypted files below |
| `vault.yml` | yes, encrypted | the one hand-written secret file: private variables/tokens/passwords, see `secrets.example.yml` |
| `proxmox-token.yml` | yes, encrypted | Proxmox API token, written and encrypted by the machine-config stage |
| `state/<layer>.tfstate` | yes, encrypted | every layer's OpenTofu state -- the `backend` block in each layer argues why it is in git at all |
| `guests-ssh-key` | no | ssh key with the initial trust to the guests, written by the guests layer |
| `talosconfig` | no | talosctl credentials, written by the cluster layer |
| `kubeconfig` | no | kubectl credentials, written by the cluster layer |

> non committed files can be regenerated by running their source tofu stages

### Committing across both repos

A `tofu apply` changes two repos: the layer here, and the state in `secrets/`.
Stage what you changed and let one task close both:

```sh
git add cluster/
mise run save "cluster: a second control plane"
```

It commits the submodule first (the pointer cannot exist before the commit it
points at), commits here, and then attaches a `git note` to the submodule
commit naming this one.

### How they reach a stage

`scripts/tofu.sh <layer>` decrypts what that layer needs and exports it as
`TF_VAR_*` or provider env vars, then runs tofu.

### What is in OpenBao

The vault above only bootstraps the lab. Everything a *workload* needs lives
in OpenBao, in the `kv` v2 mount, and reaches pods through external-secrets:
an `ExternalSecret` names a path, the `openbao` ClusterSecretStore reads it
(read-only, authenticating with its own ServiceAccount token) and materialises
a Secret.
